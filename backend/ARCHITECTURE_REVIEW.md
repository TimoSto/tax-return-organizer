# Architecture review of `backend/` (hexagonal Go)

## Scope
Review of `backend/` for architectural weaknesses and best-practice violations. Everything under `backend/` (~3.4k LOC non-test) was read: core, ports, use cases, HTTP adapter, Postgres/fake adapters, composition root, both `cmd/` entrypoints, golangci config, migration.

**Overall verdict:** the structure is unusually disciplined for a WIP project. Layering is machine-enforced (depguard), aggregates have private fields and rehydration validates stored data, repositories share contract tests (`porttest`), tx handling is correct, the Transactor is a clean port. The weaknesses below are mostly about **tenant security/identity, enforcement gaps, and a few leaky seams**, not about the basic shape.

## Findings (ordered by severity)

### High
1. **The 4-char collector id is the only access control, and it is enumerable.**
   `domain/collector_id.go` (4 chars × 31-symbol alphabet ≈ 923k ids) + `tenantFromPath` in `httpadapter/routes.go` (tenant = URL segment). `GET /collectors/{id}` returns the collector's **email** (PII) and 404-vs-200 is an existence oracle, so the whole tenant space can be scraped in ~1M requests. `POST /collectors` is unauthenticated and unthrottled and writes 1 + 2 personas + 5 items per call (write amplification, id-space exhaustion; birthday collisions get likely at ~1k tenants and `maxIDAttempts = 5` then returns a 500). "No auth yet" is documented, but this is deployed via `cmd/docker`, so treat the short id as public. Fix: do not ship publicly before auth; meanwhile make the id longer/non-guessable, or at least rate-limit + drop email from `GET`.
2. **Tenant isolation is by convention only.** *(Resolved for personas: `port.PersonaStore.For(collectorID)` returns a repository bound to one collector; new tenant-owned resources must follow this pattern. Postgres RLS remains an optional extra layer.)* Every future use case must remember to pass `collectorID` to the repo; nothing structural prevents a repo method without it (`GetCollector(id)`, `SavePersona` derives it from the entity). For multi-tenant SaaS add defense in depth: tenant-scoped repositories (`repos.For(collectorID)`), and/or Postgres RLS (`SET LOCAL app.collector_id` in `Transactor.InTx`). Do this *before* clients/uploads arrive, it is cheap now and painful later.
3. **Lint rules do not enforce the architecture the docs promise** (`.golangci.yml`). depguard only blocks *module* imports in `domain`, so `domain` may import any third-party/stdlib (it already imports `uuid` and `crypto/rand`), and `core/**` may import `net/http`, `pgx`, `database/sql`. Missing rules: core must not import `net/http`/`github.com/jackc/*`/`database/sql`; use cases must not import each other; `port` must not import `usecases`; `domain` allow-list (stdlib subset + uuid) rather than deny-list; HTTP resource packages must not import each other. Also add `exhaustive`, `gosec`, `sloglint`, `contextcheck`.

### Medium
4. **Wrong comment hides a modulo bias** — `collector_id.go:12`: alphabet has **31** chars, not 32 (verified), so `b % 31` over a byte is biased (first 8 symbols ~12% likelier). The SQL CHECK regex has the same 31. Fix with rejection sampling or `rand.Int`/`rand.N`, and correct the comment.
5. **Domain owns infrastructure concerns.** *(Resolved: `port.{Collector,Persona,Item}IDGenerator`, random impl in `adapters/outbound/idgen`, `ErrInvalidLocale` now in `personatemplate`.)* `domain.IDGenerator` + `RandomIDs` + package-level `NewCollectorID()` (crypto/rand) live in `domain`, contradicting the interface's own "domain stays deterministic" comment; two parallel ways to generate a collector id. The interface bundles three unrelated generators (ISP). Move to a `port.IDGenerator` (or per-aggregate funcs) with the random impl in an adapter/`idgen` package. Related: `domain.ErrInvalidLocale` lives in `domain/errors.go` although `Locale` belongs to `personatemplate`.
6. **Test seam in production code.** *(Resolved: the option is gone, callers pass an `IDGenerator` embedding `idgen.Random`; e2e builds its transactor via `backend.NewTransactor`.)* `createcollector.WithIDGenerator` exists only so `cmd/e2e` can seed id `aaaa`. And `cmd/e2e` re-implements the repository wiring (`port.Repositories{...}`) that `backend.postgresRepositories` already has → drift risk. Export a `backend.NewCreateCollector(pool, opts...)`/seed helper from the composition root and have e2e use it.
7. **Error contract is human-text only.** *(Resolved: RFC 9457 `application/problem+json` with a stable `code` per `domain.Error`, `httpx.DecodeJSON` for 413/415/trailing data. Mux-generated 404/405 are still plain text.)* `httpx.WriteError` returns `{"error": "<english domain message>"}`; the BFF has i18n, so it must string-match. Add a stable machine `code` (e.g. `collector_not_found`) per domain error, ideally RFC 9457 `application/problem+json`. Domain messages then stop being presentation text. Also: `MaxBytesReader` overflow is reported as 400 instead of 413, trailing JSON after the first object is silently accepted (`dec.More()`/second `Decode` check), no `Content-Type` check.
8. **Stringly-typed routing metadata.** *(Resolved: `httpx.Route.Tenant` marks tenant-scoped routes, `withTenant` takes a swappable resolver, `checkPathTenants` fails startup when flag and pattern disagree, param names are constants.)* `tenantFromPath` decides tenant extraction with `strings.Contains(r.Pattern, "{collectorId}")`; persona handlers hardcode `"id"`/`"collectorId"` literals. Make it explicit on `httpx.Route` (e.g. `Tenant bool`) or register tenant-scoped routes via a sub-router.
9. **Domain invariants missing in the aggregate.** `Persona.AddItem`/`RehydratePersona` don't reject duplicate item ids within a persona (Postgres batch would silently upsert twice); no length limits on names/titles/descriptions/metadata fields/item count (1 MiB body cap is the only bound); `CollectorID`/`PersonaID` are plain types whose zero/arbitrary values pass `RehydratePersona` unvalidated (the `domain.CollectorID(row.X)` conversions in adapters bypass `ParseCollectorID`). Collector email is not unique (duplicate sign-ups, no idempotency) and case-sensitive.
10. **Hidden input via `context.Value`.** *(Partly resolved: renamed to `RequireCollectorFrom`; the context stays deliberately as the single seam for the auth swap, and a missing tenant is a defined `ErrNoTenant`.)* Use cases read the tenant from ctx (`tenant.MustCollectorFrom`); signature lies about required input and a missing tenant is a runtime 500 rather than a compile error. Also `Must…` returns an error (Go convention: `Must` panics). Acceptable trade-off for the future auth swap, but consider an explicit `Actor`/`Principal` parameter or at least rename to `RequireCollectorFrom`.
11. *(Resolved: `/readyz` turns 503 on SIGTERM, `DRAIN_DELAY` (default 5s) before `Shutdown`, request contexts survive the signal and are cancelled only if the shutdown times out, probes log at DEBUG.)* **Graceful shutdown is incomplete** (`backend.serve`). `/readyz` keeps returning 200 while `Shutdown` drains, so the orchestrator keeps routing; add a draining flag that flips readiness to 503 first (+ small delay). `BaseContext` isn't tied to the signal ctx. Probe endpoints are request-logged at INFO on every hit (noise).

### Low / hygiene
12. *(Resolved: use cases name the operation, repositories only the failing step.)* Error prefix duplication: repo wraps `"get collector: …"` and the use case wraps `"get collector: …"` again → `get collector: get collector: …` in logs. Wrap once, at one layer.
13. *(Resolved: explicit `== nil` checks.)* `Deps.validate` uses reflection: `IsNil` panics if a non-nilable field is ever added, and a typed-nil (`(*Usecase)(nil)`) passes. Use an explicit nil-check list or generics.
14. Pass-through use cases (`getcollector`, `getpersona`) are anemic; fine for hexagonal consistency, but the read path returns full aggregates (all items) for list endpoints with **no pagination**. Plan a read-model/query port before data grows.
15. *(Kept on purpose, see its doc comment.)* `RehydrateItemDefinition` is an identical alias of `NewItemDefinition` (dead indirection).
16. Fakes (`adapters/outbound/fake`) and `postgrestest` live in the production tree as non-`_test` packages; harmless to the binary but conceptually test code (`internal/testutil/…` would be clearer). The fake transactor doesn't roll back, so atomicity is only covered by Postgres tests (documented).
17. *(Partly resolved: `MIGRATE_ON_START` + `cmd/docker migrate`, pool settings via `DB_*` env with a startup ping, `LOG_LEVEL`. Metrics/tracing still open.)* Ops: migrations run on every app start with the app's DB credentials (needs DDL rights at runtime; fine for now, split to a migrate job before scaling out); `pgxpool` uses defaults (no `MaxConns`, lifetime, health-check config, no ping at start); log level hardcoded to Info (`LOG_LEVEL` env); no metrics/tracing.
18. `httpx.WriteJSON` logs with `slog.Error` (no ctx) so the request id is lost on write failures; `recoverPanic` may try to write a 500 after the response was already started.

## Suggested remediation order
1. Security/tenancy: items 1, 2 (+ decide RLS vs scoped repos) — before any new resource.
2. Tighten depguard + add linters (3), fix id generation + comment (4, 5) — small, mechanical, high leverage.
3. Error codes / problem+json (7) and route tenant metadata (8) — touches `openapi.yaml`; use the `sync-openapi` skill.
4. Domain invariants (9), e2e wiring dedupe (6), readiness draining (11).
5. Hygiene items 12–18 opportunistically.
